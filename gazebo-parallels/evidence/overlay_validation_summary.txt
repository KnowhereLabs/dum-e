The actual gz_rendering_vendor 0.0.7 overlay was built successfully on the
existing ARM64 VM with colcon in 2 min 30 s. Both rendering core and OGRE
plugins were built. Warnings include unavailable optional OptiX/CUDA and
upstream compiler warnings; they are retained in overlay-build-stderr.log.
BUILD_TESTING was off: the full upstream test suite was not run.

The existing VM lacked ament_cmake_vendor_package. Its Ubuntu/ROS .deb was
downloaded and extracted under /tmp/gazebo-review/vendor-tools, then that
prefix was provided to CMake. It was not installed system-wide. The guide's
fresh-VM path instead declares this as a package-manager build prerequisite.
Other SDK/build dependencies were already present on the existing VM.

Activation returned the workspace prefix through ros2 pkg prefix. More
importantly, /proc maps confirmed BOTH libgz-rendering8.so.8.2.3 and the OGRE
plugin came from the workspace install, with private Mesa 24's virtio_gpu_dri
and GLX library. No defaults preload was used. This checks the real overlay,
not only a plugin compiled against the old core.
